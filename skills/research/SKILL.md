# 深度文獻研究技能

依研究問題搜尋、評讀並綜合文獻，交付繁體中文報告、可核對的引用與搜尋紀錄。完成程度以實際搜尋與閱讀證據為準；少量 API 結果不能宣稱完整回顧或完成系統性回顧。

## 輸入

研究主題：$ARGUMENTS。先沿用聊天、附件與既有計畫中的主題、目的、族群及限制，不因參數空白重問已知資訊。只有缺少研究問題且無法推知時才詢問；可獨立完成的搜尋策略先繼續。

未指定回顧類型時，以探索性文獻回顧起步，說明範圍與限制。若要求系統性回顧，先建立問題、方案、納排標準、適當來源與篩選／評讀流程，必要時保留待人工確認項目，不把探索性搜尋重新命名為系統性回顧。

## 執行流程

### 1. 界定問題與搜尋策略

- 介入／暴露問題可用 PICO／PECO；質性問題選合適的概念架構。量表開發、翻譯或驗證以量表名稱、構念、版本／語言、測量特性為主，不強制填治療與對照組。
- 概念內同義詞 OR、概念間 AND；依資料庫調整受控詞與語法，避免 C／O 或情境詞過早縮小搜尋。用已知種子檢查尋回，不把未測試策略稱為已驗證。
- 沿用使用者指定年份；未指定時保留原始開發／重要奠基文獻。若分析近期動向，按使用者當下日期計算近五年或近兩年的起迄日，列出實際日期與時區，不寫死年代。
- 已安裝 `pico-literature-search` 時沿用其策略、PubMed／PMC、RIS 匯入、來源稽核與全文整理流程；其他學科選相關資料庫。Cochrane／Google Scholar 依平台支援的搜尋與匯出方式執行，未執行來源明列待查。

### 2. 確認工具能力並執行搜尋

先確認當次可用工具名稱與參數；AcademicHelper 的既有能力如下：

| 工具 | 可用範圍與限制 |
| --- | --- |
| `search_papers(query, limit)` | 跨來源取回有上限的書目；`limit` 是每來源請求量，回傳數不是資料庫總命中。來源錯誤可能被省略，空結果不能單獨證明零命中。 |
| `expand_topics(seed_topic, limit)` | 固定後綴產生查詢候選，無網路與趨勢分析；人工檢查概念相關性後才使用。 |
| `deep_search(paper_doi, depth)` | 現有實作以 DOI 字串搜尋、依 `depth` 增加取回上限，未遍歷引用圖。真正的前向／後向追溯須核對來源中的引用／參考文獻。 |
| `evaluate_paper_tool` | 只產生委員／評分維度上下文，不自動評讀文獻；依實際配置可用性決定是否使用。 |
| `find_gaps` | 產生缺口候選；現有情境為臺灣護理，confidence 依結果數計算，不是缺口經驗證的機率。 |

不呼叫不存在的 `evaluate_content`。工具缺席、配置失敗或來源受限時，使用可用的來源／人工證據分析，交代限制，不假裝工具已執行。

執行核心概念、方法與相鄰主題搜尋；保留每輪來源、日期／時區、實際查詢、篩選條件、取回上限、取回數及來源狀態。只有來源實際提供時才記總命中；未知、失敗與未執行分開，均不填 0。

以正規化 DOI／PMID 去重，缺識別碼再核對題名、年份、作者；保留原來源和命中查詢。同研究不同報告、版本、評論與回覆先建立關聯，不可無理由刪除。[PRISMA](https://www.prisma-statement.org/) 用於透明報告；流程數只能由實際識別、去重、篩選與排除紀錄計算，不能把有上限的 API 取回數當完整識別數。

### 3. 閱讀、萃取與品質評估

每篇明列已審閱層級：題名／書目、摘要或全文；全文可為 PDF 或完整 HTML。萃取研究設計、樣本、情境、方法、主要結果與限制，附頁／表／段或可核對來源。不把摘要未報告當成研究沒有執行，也不從題名推算效果或方法品質。

依問題、設計及評估單位選工具，從官方來源確認適用範圍與使用版本：

- 測量研究用 [COSMIN](https://www.cosmin.nl/) 按各測量特性評方法品質；測量結果充分性與研究群體的證據確定性另列，不加總成全篇品質分數。
- 隨機介入效果用 [RoB 2](https://www.riskofbias.info/welcome/rob-2-0-tool)，非隨機介入效果可用 [ROBINS-I](https://www.riskofbias.info/welcome/home/current-version-of-robins-i)；不將兩者套給所有觀察或量表研究。
- 其他設計採相符的評讀架構，分別說明偏差、直接性、不確定性與可轉用性。研究設計、期刊影響因子與引用數均不能單獨決定品質。

全文或可核對的外部評估不足時標「待評」，不編造分數；外部評估註明文獻版本、屬性及表格位置。引用來源、工具版本與評估日期均保留，只有核實後才宣稱使用最新版本。引用數比較須採相同來源並記錄查核日期，來源缺資料或失敗不當成 0。可行時查出版者、Crossmark／PubMed 等撤稿、勘誤或更新通知；未查核須註明。

### 4. 綜合與缺口驗證

按研究問題與可比較的族群、設計、版本／語言和結果分組，區分原始研究、回顧與評論，避免重複計入同一批樣本。比較一致與矛盾發現及替代解釋；沒有足夠數據時不做合併效果或假統合分析。

將缺口列為有證據的候選：附支持文獻、實際檢查範圍、反例搜尋與仍待查資料。單次未找到、缺摘要、來源故障、研究者建議及 `find_gaps` 的文字都不證明「從未研究」。新興趨勢需有可比較年份與搜尋覆蓋，否則僅描述本次查到的近期主題。

可平行分工搜尋／評讀，再核對來源與結論；無子代理時循序完成相同檢查，不因工具配置等待不必要的確認。

## 輸出要求

- 交付研究問題與範圍、搜尋／篩選紀錄、證據表、主題綜合、候選缺口及後續建議，區分文獻結論、代理推論與待驗證事項。
- 引用只使用核實的題名、作者、年份、DOI／PMID／網址；不補造缺欄、數字或參考文獻。依指定格式輸出清單，保留各篇審閱層級及來源。
- 報告說明截取、來源失敗、未取得全文、品質待評及人工篩選進度；完成搜尋策略或下載 PDF 不等於完成納入與評讀。
- 要求 Zotero 時，先確認 `setup-zetero`／`zotero-literature-import` 是否已安裝與配置；API key 僅從 `ZOTERO_API_KEY` 環境讀取，不寫入報告或聊天。只在入庫流程實際執行並核對後宣稱入庫完成。
