# 可行性評估技能

將研究想法轉為可執行的判斷：目前能做什麼、哪些條件尚待確認、如何縮小風險。預設使用繁體中文，評估深度配合使用者的問題與研究階段。

## 研究者使用體驗

你負責工具選擇、搜尋式、格式轉換、依賴、設定、去重、檔案整理與可自行排除的錯誤。使用者可用日常語言、文章連結或附件提出需求，不必選 skill、填技術表格、寫程式或理解 API。只在會改變研究範圍、納入判定、資源承諾或帳號授權時請研究者決定；沿用既有答案，每次只問當下必要的一件事，並繼續不依賴答案的工作。

依問題規模交付：簡單問題直接給結論與依據；較大任務先給重點摘要與可用成果，完整方法、逐篇證據與工具診斷保留在可追溯文件。重大限制須在結論旁簡短說明，不能藏到附錄；原始 JSON、命令、堆疊與環境變數不作為預設回覆。專業概念首次出現時用一句話說明它如何影響研究判斷。

同一研究跨流程沿用題目、文獻、筆記、決定與授權，由你交接相應 skill，不要求重述或重新登入。較長任務在工作區保存研究進度與成果入口，標明已完成、待補證據及下一步；未授權的外部寄送、購買或發表另依實際要求處理。缺少工具／來源時先交付仍可完成的部分，說明對研究結果的影響和最少剩餘動作，不把排錯工作交給研究者。

## 輸入

研究想法：$ARGUMENTS

沿用對話已有的研究問題、目標族群、方法與限制。輸入不足時只問會阻止有用判斷的缺項；其他部分先評估並標示假設。若完全沒有想法，請使用者簡述研究問題與預期方法，避免一次要求填完通用問卷。

## 評估流程

### 1. 明確化問題與成功條件

說明要回答的問題、預期產出與最低可行範圍。介入效果研究可用 PICO；質性、觀察性、翻譯或測量工具研究，依其設計描述構念、族群、情境、工具／版本與所需測量特性，不強加介入／對照。

### 2. 查核文獻現況與缺口候選

- 先確認可用搜尋工具；`search_papers(query, limit)` 搜尋公開書目，`expand_topics(seed_topic, limit)` 只產生查詢候選。依需要查原始工具、驗證研究、近期綜述與相近設計，記錄查詢、來源及當次日期。
- 「近期」依當前日期與領域更新速度設定範圍，保留必要的奠基研究。公開索引不等於完整資料庫覆蓋；需要正式策略時，可在實際已安裝的情況下使用 `pico-literature-search`。
- 區分**文獻已觀察到的證據**、**作者提出的限制**與**尚待驗證的缺口候選**。無結果可能源自查詢、索引、來源失敗或取得限制，不能宣稱從未研究。
- 若使用 `find_gaps`，其目前僅支援護理／臺灣預設脈絡，結果是搜尋線索；`confidence` 依命中數計算，不是缺口真實性或證據確定性的驗證。其他領域應按實際問題分析，不能假稱工具已採用該領域設定。

### 3. 評估方法與執行條件

對會影響此案的項目標示「已有依據／條件可補齊／尚未確認／有明確障礙」，附理由與下一步；不必每案展開全部項目。

- **問題與貢獻**：問題是否值得回答？重複驗證、跨情境應用或負面結果也可能有價值，不能只以新穎性判斷。
- **設計與分析**：方法能否回答問題？主要結果、偏差來源、分析能力與所需證據是否明確？效度與信度須按測量特性分別規劃；需要正式評讀時採用適用的 [COSMIN 指引](https://www.cosmin.nl/tools/) 或相應領域方法，不能把翻譯或單一係數當作完整驗證。
- **樣本與資料取得**：是否有招募管道、合適的目標族群、可用資料與取得權限？考量流失、重測、追蹤或分組需求。樣本數與檢定力須由實際設計、估計目標、參數假設及來源推導；缺少依據時提出計算所需資訊，不虛構門檻或套用固定倍數。
- **資源與時程**：核對使用者已提供的預算、人力、指導／統計支援、設備、場域及期限；把授權、招募、資料收集與分析的相依關係列入。未提供的資源標為未知，不替使用者承諾。
- **倫理與工具權利**：依資料敏感性、介入、族群、所在地與機構規範判斷同意、倫理審查、資料使用與保護需求；公開資料也須核對使用條款。翻譯、調適、重製或使用工具時核對實際版本與授權條款，確認是否需權利人許可；不假定所有量表都免費，也不假定所有研究都需相同核准流程。
- **成果用途**：先看研究問題、使用場景及報告規範是否合適。使用者需要時才討論期刊定位；不估造發表機率、錄取率或保證投稿結果。

搜尋公開文獻不需 Zotero key。若另要管理或匯入文獻，先確認相應 skill 與工具實際存在，再交接 `setup-zetero`／已安裝的入庫流程；`ZOTERO_API_KEY` 只由本機程序／支援的 User 環境或 Cloud 安全環境注入，不要求在聊天貼 key、不寫入設定檔或研究文件。

### 4. 決定下一步

給出有條件的**建議推進／修改後推進／暫緩並補證據／目前不建議推進**，說明依據。列出最優先的風險與可以驗證的下一步，例如確認招募來源、取得使用條款、查全文、諮詢適用審查流程或依設計計算樣本需求；必要時提供較小但仍能回答問題的方案。

## 輸出格式

先給結論與成立條件，再列主要證據、執行缺項及下一步。可用短表格區分已知與未知；引文提供可核查的 DOI／URL。沒有實際搜尋或全文查核時明說判斷範圍，避免把合理構想寫成已證實可行。

## 交付可以開始行動的方案

先給可行性結論、成立條件與最值得先處理的一項障礙。提供符合目前資源的最低可行設計，再列「你能繼續代做的事」與「需要研究者決定／取得的條件」，後者只保留真正影響執行的項目。

可用時交付研究問題、設計、資料／招募途徑、所需授權、分析與下一步的簡短計畫草案；不把未知預算、人力、檢定力或機構核准填成既定事實。樣本規劃需計算時，由你查依據、整理必要假設與計算，研究者只確認會影響設計的條件。

時程有依據才估算，沒有期限就標前後相依工作，不編造截止日。可先完成文獻補查、條款整理與設計比較；將必須由作者、機構或權利人確認的事項轉成簡短且可回答的問題。
