# 讓研究者專注於研究

AcademicHelper 的工作是把研究問題變成可用成果。研究者負責研究目的、納入條件、資源承諾、倫理與權利判斷；助手負責查找、工具操作、轉換、整理、核對與交付。

## 使用方式

描述想回答的問題、提供文章或附件即可。助手沿用已有上下文並選擇合適流程，不要求先挑 skill、填 PICO 表、寫搜尋式、查技術編號或理解 API。資訊不完整時，先處理可完成部分；只追問會影響研究判斷或必要授權的項目。

簡單問題給簡短且有依據的答案。較大任務先呈現研究結論、可使用的成果入口及最重要的一步；逐篇證據、查詢、時間、來源、篩選與排除紀錄保留在可查核文件。重要限制會改變結論時，直接放在結論旁，不埋在技術附錄。

## 每個流程的交付

| 流程 | 研究者可直接使用的成果 |
| --- | --- |
| 文獻回顧 | 重點結論、分歧與缺證據；優先閱讀及理由；可編輯證據表與報告 |
| 研究方向 | 優先建議、替代方案的取捨、可討論的題目／設計草案及最小驗證步驟 |
| 文獻關聯 | 可用在研究何處、依據與限制；有既定納排條件時提供候選判定供作者審核 |
| 可行性 | 有條件的結論、最低可行方案、助手可繼續代做與需要作者決定的事項 |
| 修稿／口試 | 優先問題、原文／證據位置、具體修稿建議；問題、現有回答依據與待補證據 |
| 文獻與全文整理 | 開始閱讀入口、已核對存在的全文、閱讀清單及待取得全文；未完成來源清楚標示 |
| Zotero 連接 | 助手處理可用設定與檢查；研究者只選必要文庫或完成安全授權 |

學術專業概念會說明它對研究判斷的影響。題名、摘要與全文的證據程度分開；引用數、期刊或模型角色多數不能代替研究品質。可編輯草稿不冒充正式納入判定、實際結果或機構核准。

## 文獻成果入口

搜尋整理 helper 產生 `開始閱讀.html`，顯示實際候選數、可用全文與待取得狀態，連到當次成功匯出的 Excel、已有清單及可開啟文獻。搜尋失敗、尚未執行、部分取回與 Excel 未完成均清楚呈現；沒有候選不等於沒有研究。

資料多時交付成果目錄或完整下載包，原始材料保留。助手檢查成果中的連結與 PDF，位於原環境的本地路徑不能當作可攜下載；必要時依授權複製到成果目錄。閱讀筆記與篩選決定在更新前保留、合併並核對，避免重新匯出造成遺失。

## 不中斷研究的處理方式

一個來源不可用時，繼續其他來源並回報對研究涵蓋範圍的影響。缺全文仍保留書目與可查入口；缺 Excel 匯出能力先提供閱讀入口及可用清單，標記剩餘交付。助手先排除可自行修復的工具問題；只有帳號登入、機構權限、作者許可或研究取捨真的需要作者時，才提出最短的必要動作。

跨流程傳遞相同題目、文件、決定和授權；長任務留下研究進度與成果入口，讓後續工作接續。只連到實際存在的成果，不用「已完成」掩蓋尚未搜尋、評讀、寫入或驗證的部分。

## 維護時的檢視情境

- **已有題目但參數空白**：沿用上下文，先產出可用內容，不要求重填研究描述。
- **只有一篇文章問用途**：短答用途、依據、閱讀深度與限制，不產生通用問卷或龐大評分表。
- **來源失敗或無全文**：保留已找到的材料，說明重要缺項；不把失敗／未執行填成零命中。
- **已選研究方向**：直接接續可行性或文獻流程，沿用決定而非重問。
- **已有筆記又要更新清單**：保留並核對合併結果；不覆蓋後請研究者自行補回。
- **研究者準備口試**：交付能修改與練習的內容，角色全文回饋留在報告，重要分歧仍可查核。

這些是流程與產出的檢視準則；靜態文件檢查與離線 helper 測試不代表已完成真實研究者使用測試或資料庫搜尋。
