# 助手用：讓成果容易找到

使用者只需記得一個檔案：研究工作區根目錄的 **研究入口.md**。它指向各流程目前可用的成果，不要求使用者辨識 skill、執行日期或原始資料格式。這是所有 skills 的交付約定，由助手實際維護；本次文件更新沒有新增自動建立目錄或更新入口的程式。

## 一個專案、一個入口

沿用已有研究工作區；不同研究題目才分專案，跨 skill 不分新的專案。新研究使用清楚的研究名稱作目錄名稱，檢查撞名與既有內容後才建立。已有 `evidence/`、`notes/`、`outputs/` 等結構就沿用、連結，不批次改名或搬移。

```text
<研究工作區>/
  研究入口.md                       ← 研究者從這裡開始
  研究概況.md                       ← 題目、範圍與必要決定
  閱讀筆記/                         ← 長期人工筆記，不被重跑覆蓋
  outputs/
    成果/
      README.md                     ← 每種用途的最新可用成果
      20261008-143000-文獻搜尋/
        開始閱讀.html               ← helper 產生的閱讀入口
        研究摘要.md                 ← 助手寫的有來源摘要
        文獻清單.xlsx               ← 僅在匯出成功時存在
        文獻清單.csv
        pdfs/                       ← 可用全文
        raw/                        ← 查核用原始資料
        manifest.json               ← helper 所需紀錄
        搜尋式.html
      20261008-153000-研究方向/
        研究方向.md
        證據表.csv
        查核紀錄/
      20261009-100000-修稿與口試/
        修稿與口試.md
        修改清單.csv
        查核紀錄/
```

以上只是結構範例，不表示已有這些成果，不提前建立所有空資料夾。日期用使用者時區，入口寫明時區；同秒撞名加序號。用途使用文獻搜尋／研究綜合／研究方向／適配判斷／可行性／修稿與口試，檔名採研究者易懂的名稱，避免只有技能名稱、final2 或 latest。因 OS 不允許的字元由助手整理，不讓使用者處理。

## 固定入口如何更新

`研究入口.md` 保留使用者已有文字，加入或更新助手管理的成果區塊。內容是目前題目、一句進度、值得先開的成果、重要待補及下一步。首次建立時可用下列格式；未有實際檔案就寫待完成，不產生虛假 Markdown 連結。

```text
# 我的研究
研究題目：<已確認題目>
目前進度：<實際完成範圍>
先開這份：<主要成果的有效相對連結>
其他成果：<outputs/成果/README.md 的有效相對連結>
需要留意：<影響判斷的未完成來源／全文／授權>
下一步：<一個可執行的研究動作>
```

`outputs/成果/README.md` 用一個簡單表格列用途、最新可用檔案、更新時間、完成範圍與待補。每種用途只給一個主要入口；完整任務紀錄另列歷史連結，不把所有 JSON／PDF 一次堆給使用者。任務部分成功時標示其覆蓋；最新一次失敗且沒有可用成果時保留前次可用連結，旁註本次失敗，不把前次冒充本次。沒有既有成果就明列尚未產生。

入口連結使用相對路徑，解析位置是該入口所在目錄；中文與空格路徑用 Markdown `<...>` 包住並實際驗證。助手回覆先給研究入口與本次主成果，通常最多三個主連結。技術查核不是預設閱讀順序。

## 保存、重跑與可攜性

- 每次新任務建新目錄，不覆蓋人工報告／筆記。PICO 明確 `--out outputs/成果/<新任務>/`；同次 `import`／`rank` 對既有目錄重輸出前先保存人工 Excel 筆記，工具不會將筆記回寫 JSON。
- helper 的 HTML、CSV、XLSX、pdfs、raw、manifest 保留原有相對位置，不為外觀拆開搬到全域資料夾。其他 skill 可將診斷／原始證據留在任務內 `查核紀錄/`；主要摘要仍在頂層。
- 舊成果留在原位，由歷史入口導覽，不自動清理、不多複製一份「最新」資料。多篇共用 PDF 可沿用既有位置；跨環境需交付完整 bundle 或授權允許的全文副本並核對連結。ZIP 僅在需要可攜交付時製作，先排除憑證、私有設定與不允許分享的內容。
- `plan` 只連搜尋式，不承諾開始閱讀；XLSX 匯出失敗保留 CSV／HTML 並明列未完成。閱讀入口不得把舊 XLSX 當作目前成功結果。
- Zotero setup 通常只需聊天狀態；需要留紀錄時放不含憑證的簡短設定檢查說明，不建一批空資料夾，也不保存 key metadata 原始回應。簡單適配問答同樣不強制生成檔案。

## 交付前驗收

從研究入口逐一解析主連結，確認存在且能打開；確認各類最新成果實際日期與狀態。開啟表格核對列數／欄位，PDF 核對內容，HTML 檢查全文與清單連結。重要限制留在主要成果旁；舊版、失敗、部分完成與待授權清楚區分。遇到既有人工編輯保留內容並合併，而不是整檔覆寫。
