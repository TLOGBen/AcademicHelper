# 助手用：初始化研究專案

初始化的是研究工作區，不是新軟體產品。不要生成多餘的應用程式、Git repository、套件或資料庫。先沿用目前的研究目錄與對話；保留已有文件、倫理審查資料、閱讀筆記與產出。

完整命名、版本與入口更新規則見 [成果資料夾設計](output-layout.md)。

## 找到真正要研究的問題

從已有內容整理研究主題、目的、研究對象／構念、語言與版本、成果用途及已知資源。題目不足時先問一個容易回答的問題，例如「你想研究什麼，或希望我先幫你完成哪件事？」不要一次交出所有必填欄位。PICO 適用時整理成 PICO；量表翻譯／測量研究可改用族群、構念、版本及測量特性，不硬套介入研究。

把已確認、暫定與未知分開。沿用已有研究判斷；研究者不用自己寫設定檔。未確認的倫理核准、授權與研究資料不可補成已取得。

## 建立最小工作區

在實際研究工作區內建立缺少的入口，以下是可調整的建議結構，不是工具要求。已有相同用途目錄就沿用，不搬動原檔。

```text
<research workspace>/
  研究入口.md
  研究概況.md
  閱讀筆記/                 # 使用者的長期筆記與納入判定，保留來源位置
  outputs/
    成果/
      README.md             # 各流程最新可用成果，助手維護
      <任務識別-用途>/      # 報告、清單、全文與完整工具輸出
```

`研究入口.md` 放目前題目、下一步與可點開的最新成果；`研究概況.md` 簡記目的、族群／構念、已知文獻、資源與待決定事項。不要把個人憑證或受限制的原始研究資料複製進公開 checkout。在 plugin checkout 工作時可用已忽略的 `outputs/<project>/`，研究資料若要版本管理或共享，先確認實際儲存與授權範圍。

以可用日期／任務識別建立新的輸出目錄。把引用、檢索日期、資料庫、搜尋式、查詢上限、失敗及未執行來源留下紀錄。原始 API 回應可能含研究內容，保留在適當工作區，不自動發布。

## 接上第一個工作流程

依 [tools.md](tools.md) 選 skill；研究者不需選。若要 PICO 搜尋，由助手從已確認題目建立非敏感 profile，參考正式 skill 的欄位與搜尋策略文件，使用明確 `--config`；內建 GSEOH 範例只能用於相符題目或明確的 smoke check。

如需 Zotero，檢查是否已有連接；沒有則執行 setup-zetero。初始化不以寫入 Zotero 為必要條件。文獻入庫須確認本機入庫 skill 存在、目標與使用者寫入要求，不能用 setup 代替。

第一個交付應是可閱讀的研究概況／搜尋策略／證據摘要，並附下一步。涉及 Excel、PDF 或 HTML 時實際開啟並核對成果；跨電腦交付要處理原環境的絕對路徑，保留原檔，備妥授權允許的可攜副本並驗證連結。

完成後告訴研究者成果入口與一個符合目前題目的指令，例如「幫我找這個題目的核心文獻，整理可讀全文與閱讀清單。」已初始化不代表已完成系統性回顧。
